# Imatrix project — complete integrated package

This is the complete imatrix research package, **not a patch**. The chat-template evaluator, sample logging, importance-matrix analysis, quantization, and reporting are already included. It does not replace the team's `src/` files.

## Installation

Extract the ZIP so that the **single `imatrix_project/` folder** lives inside your original repository next to `models/` and `results/`:

```text
CMSC473-Exploring-Quantization-Stability-using-Llama.cpp/
├── models/                   # Existing GGUF checkpoints and imatrices
├── results/                  # Existing output
├── src/                      # Original team code, unchanged
└── imatrix_project/          # This complete new folder
    ├── imatrix/              # Python package
    ├── tests/
    ├── requirements-imatrix.txt
    └── README.md
```

From the main repository root:

```bash
cd imatrix_project
python -m pip install -r requirements-imatrix.txt
python -m unittest discover -s tests -v
python -m imatrix evaluate --list-models
```

The package automatically resolves the main repository as the parent directory. You can also pass `--root ..` explicitly to `evaluate` or `quantize`.

## Run the corrected chat-format evaluation

First try a small smoke test. `--max-new-tokens 64` is only for testing, not for reporting scientific accuracy:

```bash
python -m imatrix evaluate --models uniform-q4 --limit 1 --experiment imatrix-chat-smoke-v2 --prompt-format chat --threads 8 --max-new-tokens 64
```

The evaluator writes `../results/imatrix-chat-smoke-v2/uniform-q4/metrics.json`, `samples.json`, `performance.json`, and `protocol.json`.

Next compare all four Q4 configurations with the same 20 examples per task and consistent generation caps:

```bash
python -m imatrix evaluate --models uniform-q4 chat-q4 math-q4 code-q4 --limit 20 --experiment imatrix-chat-q4-n20 --prompt-format chat --threads 8 --max-new-tokens 512
python -m imatrix evaluate --experiment imatrix-chat-q4-n20 --report-only
```

The summary is `../results/imatrix-chat-q4-n20/benchmark_scores.csv`. Each model has its own `samples.json` for inspecting exact answers. The GSM8K results include strict and flexible extraction metrics; generative MMLU is **not** standard likelihood-based MMLU. Avoid mixing the earlier raw-prompt results into this chat-prompt run.

**Compute note:** `--gpu-layers 0` uses CPU-only llama.cpp. BF16 can be extremely slow; these example commands select quantized models explicitly.

## Full imatrix workflow (reuse existing files)

```bash
python -m imatrix analyze
python -m imatrix recommend --high-fraction 0.25
python -m imatrix quantize --dry-run --precisions Q4_K_M Q6_K --include-mixed
python -m imatrix evaluate --list-models
```

To perform quantization rather than preview it, remove `--dry-run`. Existing imatrix files are expected at `../models/imatrix/{chat,math,code}.imatrix.gguf` and aren't regenerated by `analyze`.

For P1 sensitivity correlations, first supply your measured layer-sensitivity CSV and see:

```bash
python -m imatrix correlate --help
python -m imatrix compare --help
```

## Important limitations

The evaluator uses `/v1/chat/completions` to apply the GGUF model chat template, but the underlying prompts and metric filters remain those of the selected LM Evaluation Harness tasks. This defines a **different protocol** than earlier raw-completion results. It doesn't implement true teacher-forced token likelihood and won't validate historical HellaSwag likelihood scores from the recovery branch. This package hasn't been evaluated end-to-end on your local Mac models; tests cover local Python/CLI behavior only.
